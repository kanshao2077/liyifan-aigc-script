# 脚本诊断与修改边界

## 先写清教学承诺

内部用一句话回答：观众看完后，能判断或完成什么？口播中的开头、案例、方法和结论都应服务这一个结果。若一篇同时承诺多个互不相干的结果，优先收窄，而不是用更多花字掩盖。

## 六项诊断

1. **开头是否给出真实观看理由**：具体问题、可感知差异或明确结果优先；不要只喊“高级感”“电影感”。
2. **案例是否能证明观点**：画面和声音必须真的包含正在解释的变量。正文说“这里”时，分镜应立即给出对应案例、界面或波形。
3. **实验变量是否一致**：声称只改声音，就不能同时改镜头顺序、长度、黑场和画幅；若实际改的是完整剪辑设计，就把承诺改准确。
4. **教学闭环是否完整**：问题/错误 → 改动 → 回放 → 原因 → 可复用方法 → 适用边界。只有术语和结论，没有回放或操作，不算教会。
5. **信息是否重复**：同一个公式可以经历“先感受、再命名、再操作、最后总结”，但每次出现要增加新信息，不能只换句话重复。
6. **事实与身份是否真实**：区分已有素材、本次实测、计划演示、行业常识和推断。品牌、软件按钮、模型能力、价格、成功率和耗时需要核实。

可在内部给段落标记功能，检查教学闭环：`P 问题`、`E 证据`、`D 演示`、`X 解释`、`T 迁移`、`S 总结`、`CTA 行动`。这是一套工作标记，不输出到口播。缺证据时只是观点，缺演示时不是教程，缺解释时观众不知道为何有效，缺迁移时观众只能照抄当前案例。

每句重复应承担不同任务：第一次命名概念，第二次跟随演示执行，第三次变成观众的检查题。没有新增证据、操作、因果或迁移的同义复述应合并。

## 自动小改与停下来问

可直接小改并说明：

- 修正承诺与实际演示的明显矛盾。
- 删掉不改变信息的重复句。
- 把抽象判断改成可观察的画面、声音或操作。
- 把“已经做过”改成与真实状态一致的“准备做/待验证”。
- 调整短句顺序，让案例先被看到，再给结论。

需要问一个问题：

- 核心案例或素材是否真实存在，答案会改变整套分镜。
- 用户必须在两个不同教学结论之间选择。
- 需要新增付费素材、外部发布、品牌授权或其他新权限。
- 关键事实无法从资料核实，且不能用明确的条件表达绕开。

即使需要提问，也先完成不依赖答案的部分，并明确两种答案分别影响哪些镜头。

## 研究方式

- 工具、平台、模型和规则优先查官方文档。
- 剪辑方法优先查软件厂商教育资料、专业剪辑师一手访谈和可靠影视教学资料。
- 讲“为什么有效”时，把公认原则与针对本片的创作判断分开。
- 不把单个视频博主的经验包装成普遍定律；可作为灵感，不作为唯一证据。

关键判断可临时标成 `[FACT]`、`[OBSERVED]`、`[JUDGMENT]`、`[HYPOTHESIS]`、`[PLAN]`、`[PROMISE]`。计划不能写成已经发生，审美判断不能写成普遍事实，资源承诺没有真实位置时必须标待确认。

## 迁移、总结与 CTA

- 至少判断方法能否迁移到另一个场景，并说明保持有效的机制。汽车案例可迁移到产品亮相、人物登场或空间转场，但要继续遵守“先建立期待、高潮前减信息、最后集中释放”。
- 总结要变成可执行检查，不是再念一遍课程内容。
- 一条视频只设一个主 CTA。资源 CTA 必须有真实领取位置；没有时留待确认。优先给与课程直接相关的最小练习或让观众选择下一种案例。

## 李一帆口吻的保留项

保留教师陪练感、问题先行、案例 A/B、边演示边解释、自然复用“老规矩”“我们来看”“还想学点啥”。不要为了分镜把口播改成课程提纲、机构报告或密集术语。脚本有问题时改具体机制，不抹掉本人语气。
