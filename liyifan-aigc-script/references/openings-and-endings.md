# 开场、转场与结尾

## 开头六类：人工主类型编码

每篇按开头主导的观看理由只归一类，混合性质在样本表注明。计数基于29篇，不代表真实完播效果。

| 类型 | 篇数与样本 | 观看理由及适用题 |
| --- | --- | --- |
| 失败/质感落差先行 | 14：02、03、07、09、10、13、15、16、19、21、25、26、27、29 | 观众先认出自己的问题；适合排障、声音、剪辑、画面知识 |
| 新能力与低门槛结果 | 8：01、04、05、06、08、12、17、20 | 展示原本困难的结果现在如何开始；适合新工具与完整流程；20是直接资源演示型变体 |
| 热点/升级后的新麻烦 | 3：14、22、28 | 大家听说过的能力落到实际使用的卡点；适合新功能边界、预算和复杂控制 |
| 展示结果或对照先行 | 2：23、24 | 23用两种制作结果比较，24用空间感效果组；适合肉眼可辨的影视知识 |
| 行业疑问 | 1：11 | 从少人数与产能反差追问工作方式；效率协作题，不能编造行业普遍数据 |

频繁使用的是前两类，后四类是为不同任务保留的变化，不宣称同样高频。

## 开头怎么安排

原稿没有可核对的秒数。下列是本Skill的创作目标：前3—5秒给一个具体观看理由；前10—15秒说清“今天带你做/判断什么”。身份介绍放在钩子之后或留到结尾，避免拖慢进入任务。

可选开头方式：直接让观众听两段声音；先看失去主体的镜头；拿一件商品抛出交付问题；给一段看似漂亮但叙事不清的结果。不要每篇用“你是不是也遇到过”。无实测时不要写“我测了XX次终于”。

结果展示时机：强可见差异可先展示再解释（S07、S23）；复杂流程先示成片目标再走过程（S06）；失败→原因的题先给失败再给修复（S21）。未制作的素材可以在方案中安排，不在稿中杜撰已发生的成功。

## 转场靠教学关系

- 依赖：人物确定了，声音怎样保持？（S09）
- 升级：标点只能控制语气，怎样补演员的发声方式与情境？（S07）
- 例外：有了公式但不会写，怎样把想法放进结构？（S28）
- 选择：想快速做与想精确控制，可以用不同路线。（S12）
- 暴露新问题：时间安排好，空间仍错；空间参考加入，材质又串用。（S22）

用这些因果与选择关系产生“接下来”的理由，不用章节序号替代逻辑。适度出现“那这个时候怎么办”“看懂了，我们把它放进自己的片子里”，每次后面要有新任务。

## 三类结尾主结构

1. **方法回顾→创作判断→身份与继续学**：S02、07、09、10、11、13、14、15、16、19、22、24、25、26、27、28、29等。保留最有用的二三项，落到人如何做决定，不空泛赞美AI时代。
2. **完整结果/流程价值→身份与下期邀请**：S01、05、06、08、18、20、23等。结果必须真实可呈现，不虚构节省时间或交付质量。
3. **适用对象/选择条件→复盘→身份与CTA**：S12、21尤其明确。给新手、精细控制或局部故障各自的选择，让观众知道下一次怎么用。

结尾模式可重叠，不把上述列表当互斥频数。S03、04还重申连贯成片/产品链与配套资料。每篇完整收尾分析见样本表。

固定身份以用户确认的“我是AI界人民教师一帆”为准；可接“还想学点啥，我们下期接着聊”“我们下期接着学”，或按主题征集具体问题。不要加入未经用户要求的销售、私信领课和外链导流。

资料提醒必须属实：交付了Prompt说明可提醒查看；仅规划资料时改成给可记下的关键词。源稿中的“开源了/上传了/无广”不是自动可继承的CTA。
